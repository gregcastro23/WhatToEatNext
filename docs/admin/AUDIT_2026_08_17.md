# Admin surface audit — 2026-08-17

Nine parallel auditors read every admin tab, followed each `fetch` to its route, each route to its service, and each service to its SQL. Every finding below then went to an independent adversarial verifier instructed to **refute** it and to default to refuted when uncertain. An honest `live: false` empty state was explicitly *not* counted as a defect — that is the documented required behavior in `CLAUDE.md`.

**121 findings survived refutation.**

Breakdown: 47 dishonest · 14 dead · 27 thin · 33 unset.


## The shape of the problem

The admin surface was never *unwired*: ~19,000 lines across nine tabs, and every
`fetch` resolves to a real, auth-gated route backed by real SQL. The "lights on
but nobody home" feeling has three distinct causes, and they need opposite fixes:

1. **Collection without a reader.** Three tables the cron layer has filled for
   months had no admin surface at all — including `system_health_snapshots`,
   whose reader function carried the docstring *"Used for the admin sparkline /
   drift indicator"* and had **zero callers**.
2. **Liveness flags that cannot be false.** Several panels compute a `live` flag
   that is structurally pinned to `true`, so a total outage renders as a calm
   green "all sources live".
3. **Structurally empty tabs.** Moderation and Settlements read tables with zero
   rows — correctly, honestly, forever. They look broken because nothing
   explains *why* they are empty.


## DISHONEST (47)

*The panel renders a number or state that is not backed by the source it implies. The operator is actively misled — these rank first because a wrong answer is worse than no answer.*
